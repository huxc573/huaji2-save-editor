## 待增强

1. **物品 / 装备 / 技能的图形化增删**
   现在 `xj_edit` 只做了"标量就地改 + 子树自包含重写"。
   往 `@items` / `@weapons` / `@armors` 里加新条目需要往 Hash 里插一对
   （会改变成员数 → 必须整块重写并展开 `@N` 链接）；
   `xj_edit.serialize_tree` 已经支持自包含序列化，只差把它接到语义层上。
   注意 `@items` 的值是 `[数量, …]` 数组，而物品本体在 `Data\Items.rvdata2` 里
   （游戏用 id 引用），所以"加物品"只需要在 Hash 里加 `id => [数量, 0]`。
   现在只能去「全部解析数据」页搜 `@items` 手改编码值（搜 `@items` 看 `{id => [数量, 0]}`）。

2. **技能 / 装备的可视化编辑**
   `@skills`（id 数组）、`@equips`（6 个 `Game_BaseItem`）、`@exp`（Hash）
   现在只能看（角色页只读显示），改要进数据树。

3. **删掉 `I` 包装时的编码校验**
   现在写回字符串时不会附带 `:E => true` 的编码 ivar。对 ASCII 名字没影响，
   但如果以后要改**名字**为中文，游戏可能按"ASCII 字符串"读——需要时再补。

4. **GUI 还没做的**：搜索结果的"上一个/下一个"、批量改数组、
   "把 N 个物品数量一键×10"之类的便捷操作。

5. **CSV 的进阶用法**：把 `@effects` 里的 id 换成对应名字
   （比如 `解除状态#1` → `解除状态#1 中毒`），需要跨表引用
   （`Item.@effects` → `States.rvdata2`）。

6. **打包成 exe**（PyInstaller）并带上一份 `XJCodec32.exe`，方便不装 Python 的玩家。

## 已知限制（不是 bug）

- 游戏运行中改存档无效：它只在存/读档时读文件。
- 改了存档内容后**不要**再去改 `Data\main.rvdata2` / `main.dll`：
  `System\Game.md5` 里存着它们的 md5。（改存档/Data 是不校验的。）
- 存档里的 `@config[:hard_disk_code]` 是本机硬盘码，
  把存档拷到别的机器上可能被判定异常 —— 换机器玩请用游戏自己的存档。
