## 召唤兽资质：已换成内测版真值（2026-10-04 做完）

`tables/baby_aptitude.py` 现在是**内测版真值**：直接解析
`!Tools\Github\huaji2-offline-server\_work_re\eval_decoded\eval_17.rb` 的 `$baby`
（**257 条 / 5 个池**），由 `tools/gen_baby_data.py` 生成（支持 `--src` /
`XJ_BABY_RB`，`--check` 比对）。**135~254 的神兽/小孩/灵仙不再是估算值** ——
`_v201_fallback()` 只剩「真值表里没这个 id」的兜底。

生成器/表的坑（都在代码注释里）：

* `$baby` 有**三种形态**：直接数值 / `:池名`（Symbol）/ `[:池名, {...}]`（Array +
  覆盖）。脚本末尾那段 `keys.each` 就是展开规则（Symbol/Array → `_池` 的 `dup`，
  Array 再把 `v[1]` 的键并进去）。旧生成器只认单行 `key => {…}` ⇒ 257 条只抠到 193 条。
* 解析到 `:_max` 就要停 —— 它后面不是召唤兽条目。
* **`泡泡灵仙` 是个新档位**（`_灵仙资质` 池，230~237 那 8 只：hp 5500 / agi·eva 1400，
  and `life` 8000 **不是永生**）。照抄 type 会让它们从「新增召唤兽」**整批消失** ⇒
  收口成 `babies.BABY_TYPES` / `GOD_TYPES` 两个常量；`build()` 的「定值档」判据也从
  `type == "神兽"` 改成 `type in GOD_TYPES`，否则灵仙会掉进普通档、变成带随机。
* **寿命不能一刀切**：神兽是 `life == "infinite"` ⇒ 写 nil；灵仙 8000 得照表写。
* `select_type`（技能池）和 `:five`（proc）生成时丢弃 —— 编辑器不显示。

**测试侧**（这次一并修掉的假 NG）：

* `test_baby.py` / `test_gui_quick.py` 里硬编码的尝鲜版期望值（2400/7500/1.8、2100）
  一律改成从 `baby_aptitude` 取。
* 两处「按名字过滤」（`display_name(x) == "小精灵"`）改成按位置取 ——
  **真档里本来就有一只同名「小精灵」**，按名字会一次命中两只。

## 界面排版：一览表的 parent 写错 → 整页被挤成左右两栏（2026-10-04 修）

川截图「界面排版还需要优化」，实测三处：

### ① 一览表抢走整页左边缘（主因）

`_tab_baby` 里 `self.tv_babies = ttk.Treeview(f, …)` 的 parent 是**整页** `f`，
却又 `pack(side="left")` —— **Tk 的 `widget.pack()` 永远 pack 到控件自己的 parent**，
不是「最近 pack 过的那个 frame」。于是 6 行高的列表切走了 `f` 的**整个左边缘**（一直
顶到窗口底），后面的横滚动条 / 改字段行 / 字段表 / 常用+详细信息全被压成右边一条 ——
就是截图里「左边一个表格、右边一列字段」的样子。

修：`Treeview` 的 parent 改成那个专门装滚动条的子 frame `bw`（`Treeview(bw, …)`），
滚动条 + 列表先 `bw.pack(fill="x")`，横滚动条留在 `f`。
防回归：`test_gui_quick.py` 新增两条断言 —— 一览表与竖滚动条同框、
`pack_slaves()` 里一览表容器排在字段表容器之前。

### ② 一整批 Markdown 标记漏进了界面（`**粗体**` / 反引号原样显示）

Tk 的 `ttk.Label` / `tk.Text` / `messagebox` **都不认 Markdown**。踩中的地方：
说明页 `HELP_BODY` 整段（19 对 `**`）、恢复最新 / 清理所有存档 / 转门派三个弹窗、
角色页与召唤兽页「经验拉满」的 tooltip、背包计数校验那行说明。

修：全部去标记（强调统一用「」）；召唤兽页那行提示同时改短（原来 70+ 字跨两行）。
⚠ 新写界面文案别再带 `**`。自查脚本口径＝AST 扫「非 docstring 字符串里含 `**`/反引号」。

### ③ `tk.Text` 缺 `width` → 请求宽虚高 660px

召唤兽页「详细信息」的 `tk.Text(infof, height=2, …)` **没给 width** ⇒ Tk 按 80 字符
算请求宽（≈660px），把「常用 / 详细信息」那行顶到 **1332px**、页 frame 请求宽虚高到

## 已知脆弱点：手工 `LinkNode` 塞 ivar 会吞掉后续 save 的删除

`tests/probe_baby_remove.py`（⑤）实测：在 `@baby` 槽位塞一个手工构造的
`M.LinkNode(0)`（哪怕 `set_ivar` 已经把它展开成对象）之后，**同一份文档下一次
`doc.save()` 里「删掉一只召唤兽」不会落盘**（内存里删了、重读又回来了）。

* 用户路径**不受影响**：`set_active`（④）走的是同一条 `set_ivar`，测下来正常。
* 但**写测试/探针时注意**：这种人造畸形状态必须放在**另读一份文档**上做
  （`test_baby.py` 的 `@baby` 不变量那段就是这么隔离的），别留在主副本上。
* 另外 `doctree.Doc.mark_structural()` **会置 `dirty`**（doctree.py:202）——
  别以为它「只标结构、不标脏」（测试注释里曾这么写，是错的）。
