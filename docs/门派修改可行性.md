## 结论

**能做，而且只需要写一个整数。** 角色门派存在 `@sect_id`（`0` = 无门派，`1..12` = 十二门派），
改它就叫改门派；**`@skills` 和 `@sect_data` 都不用动**。

已在副本存档上跑通并验证（探针 `tests/probe_sect_change.py`，**63/0 通过**，真档指纹全程未变）：

- 改完立刻生效：`@sect_id` / 门派名 / 「本门派技能」清单 / **称谓** 都跟着变；
- 存盘重开后仍在；
- `@skills`、`@sect_data`、等级、五维、名字 **一个都没变**（只有「清空门派」才故意重置技能）；
- 改回原值可完全复原。

## 红线（实现必须守住）

1. **只允许 `0..12`。** `$sects` 是**没有 default 的普通 Hash** —— 写 13 / 负数，
   游戏里 `$sects[actor.sect_id][:name]`（35285、37033）立刻 `nil[:name]` **崩菜单**，
   而且是「所有角色一起崩」。探针已证明**现在的工具会照写不拦** → 必须加校验。
2. **别碰 `@sect_data`**：`:门派` 是按技能 id 记的计数，留着旧门派的计数无害；
   切回旧门派还能接着原来的进度。`:辅助/:修炼` 与门派完全无关（加点用的）。
3. **「转门派」不准动 `@skills`**（游戏自己也不清；顺手清就把换门派变成不可逆的删技能）。
   唯一例外是「清空门派」这条独立入口 —— 川 260927 明确要求它连带把技能重置成天生技能，
   那就必须**在确认框里写明**「游戏自己换门派不会清技能，这一步是工具额外做的」，
   并且早退条件带上技能（`@sect_id==0` 且技能只剩天生才算「无需改动」）。
4. **称谓（`@appellations`）必须跟着门派走**，但两层提前告知：
   * 门派称谓（「五庄观弟子」这种）**不能拼**（龙宫 → 「东海龙宫弟子」），必须用
     `tables/sect_appellation.py`（从拜师事件抠的 12 对）；
   * 游戏自己**只加不删**（`remove_appellation` 零调用）、也不让退/换门派，
     所以「回收旧称谓」是**工具额外做的** → 确认框里写明；
   * 非门派称谓（`内测人员` / `制作人员`）**不能误删**，显示下标也不能被抢；
   * ⚠ 早退条件也要带上称谓：真档有「门派已对、称谓错」的角色（秦媚儿），
     只看门派相同就早退，她永远修不好。

## 三个档位怎么选

| 档位 | 写什么 | 游戏里的效果 | 代价 / 备注 |
| --- | --- | --- | --- |
| ① 只改门派（推荐） | `@sect_id` | 门派名变了；门派技能页列新门派 10 个、进度从 0 攒起；旧技能照旧能用 | 最贴近「剧情事件给你换门派」的状态；旧技能留在「非本门派技能」那行提示里 |
| ② 改门派 + 学满新门派 10 个 | `@sect_id` + `@skills` | 一次到位：新门派技能全学会 | 等于「换门派 + 一键学习」两步并一步；旧门派技能还是留着（游戏行为） |
| ③ 改门派 + 清旧门派技能 | `@sect_id` + `@skills` 去掉旧门派那 10 个 | 干净：只剩新门派体系 | **不可逆**（技能没了）；职业自带技能不能动 |

按本项目一贯规矩（和 `off_sect_skills()` 的注释一致）：**①是默认，②③做成可选按钮**。

2026-09-27 实际落地的是 **① + ③的一个变体**：「转门派」＝①（`@skills` 一个不碰）；
「清空门派」＝③ 但更干净 —— 直接把技能重置成**职业天生技能**，而不是「只删旧门派那 10 个」
（等价于游戏 `clear_skills` + `init_skills`，见 `actor_reset_skills_to_class`）。
② 没做：需要「换门派顺带学满」就换完再点一次「一键学习」。

## 实现落点（已落地，2026-09-27）

- 语义层 `src/game.py`（门派段，紧挨 `sect_skills()`）—— 已按下面原样实现：

  ```python
  def set_actor_sect(self, actor, sect_id):
      """改角色门派。只写 `@sect_id`，不动 @skills / @sect_data。
      ⚠ 只允许 0..12：$sects 没有 default，越界会让游戏一开菜单就崩。"""
      v = int(sect_id)
      if v not in sect.SECTS:
          raise ValueError("门派 id 只能是 0..12（收到 %r）" % (sect_id,))
      self.sv.set_actor_field(actor, "@sect_id", v)
      return v
  ```
- 界面 `src/huaji2_save_editor.py` 左栏 `lf_learn` 那一行是
  **「门派：[下拉] [一键学习] [转门派] [清空门派]」**（后两个按钮 260927 加，同一行）：
  - `actor_set_sect()`：取下拉文字 → `SECT_NAME_TO_ID` 取 id → `askyesno` 确认
    （说明「只改门派，技能/属性不动」）→ `set_actor_sect()` → `mark_dirty()` →
    **`self._sect_actor = a`**（否则下次刷新下拉会把刚改的门派抢回去）→
    `fill_actors(keep_id="a%d" % aid)` + `load_actor()`。
    **选到「无门派」时直接转发给 `actor_clear_sect()`** —— 两条入口只能有一条实现。
  - `actor_clear_sect()`：写 0 **并把技能重置成天生技能**，且
    **`self._sect_actor = None`**（与上面相反）—— 让 `load_actor_skills()` 重新同步下拉，
    同步出来就是「无门派」；不重新同步的话下拉会赖在旧门派上，看着像没改。
    早退条件也换成 `@sect_id==0 **且** 技能只剩天生`（真档有「无门派但挂着 8 个门派技能」
    的角色，那种还得能清）。
  ⚠ 别用 `refresh_panels()`：它会把角色列表选中重置回第一行（召唤兽页踩过这个坑）。
- 下拉本身**不加**「下拉即改」语义（它只换清单）——改存档必须是显式动作（点按钮）。

  ⚠ 这是**工具额外做的**：游戏自己换门派**不**清技能（`learn_skill` 只 push + 排序），
