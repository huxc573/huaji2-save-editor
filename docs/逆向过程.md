# 逆向过程（怎么一步步走过来的）

按时间顺序记录，重点写**踩过的坑**，方便 v0.2 少走弯路。
对应的探针脚本都在 `probes/`，脚本会把结果写进同目录的 `_out_XX.txt`
（Windows 控制台是 GBK，直接 print 中文/特殊字符容易乱码或丢输出）。

---

## 0. 先看文件

`probes/probe_01_format.py`、`probe_02_files.py`

* `Data\main.rvdata2` 是**明文** `04 08 5B 06 …`（zlib 包着 Ruby 源码）。
* 其余 `Data\*.rvdata2`、`save.rvdata2`、`AutoSave\*`、`System\Game.md5`
  熵值 7.9，是密文。
* `was.info` 开头 `04 08`，但第 4 个字节起就不符合标准 Marshal（见 `存档格式.md` §5）。

结论：先得搞清楚"谁在加密"。

## 1. 找到保护框架

`probes/probe_03_dll.py`

* `main.rvdata2` 解出来只有一行：
  `Win32API.new('System/main', 'qqeat', 'v', 'v').call`
  → 一切都是 `System\main.dll` 干的。
* `System\main.dll` 是 **MPRESS** 壳（节区 `.MPRESS1/.MPRESS2`），
  所以**静态反汇编是垃圾**（前 20 条指令全是 `pushal/stosd` 之类的假指令）。
* 静态字符串里能捞到：`decryption_file` `encryption_file` `init_key`
  `http_upload` `qqeat_net_error` `System/Game.md5` `System/test.md5`
  `Audio/SE/run.dll` `Data/Scripts.rvdata2`、
  `HKEY_CURRENT_USER\SOFTWARE\...\AppCompatFlags\Layers\`、
  `\Device\HarddiskVolume1..6`、zlib 的错误串 —— 是个"通用工具库 + 防作弊"。

## 2. 解壳：LoadLibrary 之后 dump 内存

`probes/xjprobe32.cs`（32 位 C# 宿主）+ `probe_04_disasm.py`、`probe_05_unpacked.py`

MPRESS 的原始节区会被还原到**原来的 RVA**（所以导出表 RVA 不变，
但代码已经是真代码）。做法：

```csharp
LoadLibraryExW(dll, 0, LOAD_WITH_ALTERED_SEARCH_PATH);   // 触发解壳
Marshal.Copy(base, buf, 0, 0x140000);                    // dump 内存镜像
```

然后 `capstone` 反汇编 RVA `0x15F59`（`decryption_file`）等导出，得到：

* `encryption_file` → `ret 0xC`（3 个参数）
* `decryption_buff` → `ret 8`（2 个参数）
* `init_key` → `ret 4`（1 个参数）
* 0x13652 = "NULL 就换成空串指针"，说明**导出吃的是普通 C 值**。

## 3. 直接调 DLL —— 最大的坑：UTF-8

`probes/xjhost32.cs` 提供 `script` 模式：读一个脚本文件，
按行 `函数名;参数...` 调导出。

**坑 1**：参数用空格分隔 → 路径里有空格就崩。改成 `;` 分隔。

**坑 2（重要）**：用 `Marshal.StringToHGlobalAnsi`（GBK）传路径，
DLL 一律 `ret=0`、不产生输出。反汇编 `0x10DD` 才明白：

```
0x10DD(str):  0x1155(str, ...)   ; 里面 fde9h = 65001 = CP_UTF8
              0x135A(..., 3a8h)  ; 3a8h = 936 = GBK
```

→ **DLL 期望 UTF-8 字符串，自己转 GBK**。改成 UTF-8 后立刻成功。

## 4. 摸清密文形态

`probes/probe_15_format.py`（构造精心设计的明文，观察差分）

```
明文 64 字节全 0   -> 密文 72 字节 = DD7F121CA5015619 + 8CA64DE9C1B123A7 ×8
明文 4096 字节全 0 -> 密文 4104 字节 = F15D0F286B65BD28 + 8CA64DE9C1B123A7 ×512
```

* **ECB**（同一明文块 → 同一密文块）；
* 加密两次**逐字节相同**（无随机 IV）；
* 密文 = 明文 + 8（多一个"头块"）。

另一个独立证据在真实存档里：`save.rvdata2` 里有一个 8 字节块
**连续重复 3149 次**（约 25 KB）——CBC / 流密码都不可能产生这种结构。

## 5. 排错方向

`probe_10_cipher.py`：把 `save.rvdata2` 和 30 个 `AutoSave` 互相比块集合，
发现 `save.rvdata2` 与 `AutoSave\save05.rvdata2` **99.4% 的块相同**（同一次存档），
`AutoSave\save18/19/23/25` 也高度重合 —— 再次确认是位置无关的分组模式。

`probe_11_consts.py`：在解壳镜像里搜 TEA/RC5/Blowfish/AES/DES/SHA 常量，
**一个都没有** → 自定义算法。

## 6. 为什么最后没直接解密（v0.1 的遗留）

* 第三参数不是口令：`probe_20_brute3rd.py` / `probe_21_key2.py`
  试了 400+ 组合（文件名、路径、md5、中文词、整数……）全部失败；
  而且任意取值都能"自己加密自己解密"，说明它只是个旁路参数。
* `init_key` 更可能是按键表（26 次循环 + `(i, i+1)`，配合同库的 `call_input`）。
* `init()` 只做 AppCompatFlags 注册表设置。
* 直接调 `qqeat()` 会**挂住**（它按游戏进程的预期去初始化 RGSS 相关的东西），
  用后台线程等 8 秒再解密也还是空输出。

结论：密钥状态在 `qqeat` 内部的某处被装配出来，
需要继续跟 `qqeat`（impl `0x146B1`）最初的几十条指令。
详见 `docs/待解决问题.md`。

## 工具链备忘（Windows + 中文/特殊字符路径）

* 路径含 `【】[]` `!` 空格：
  * `Set-Location`/`Get-Content` 要用 `-LiteralPath`，或用绝对路径；
  * **不要用 `glob`**（`[` 会被当字符类），用 `os.listdir`；
  * `Start-Process -FilePath/-WorkingDirectory` 遇到 `[]` 会当通配符 → 改
    `New-Object System.Diagnostics.ProcessStartInfo`。
* VS Code 终端里 `& 'powershell.exe' -File '<含中文的路径>'` 有时会失效；
  最稳的是把逻辑放脚本、用 `Start-Process -NoNewWindow -Wait -RedirectStandardOutput`。
* PowerShell 5.1 控制台是 GBK：Python 打印中文/`✔` 会 UnicodeEncodeError
  → 探针里一律 `sys.stdout.reconfigure(errors='replace')`，
  并**把结果写进文件**再读。
* csc.exe（.NET Framework 自带）足够编 32 位宿主：
  `C:\Windows\Microsoft.NET\Framework\v4.0.30319\csc.exe /platform:x86`。
* 上一版的宿主 exe 被进程占用时无法覆盖 → 换个输出名，
  或先 `Get-Process -Name xxx | Stop-Process -Force`。
