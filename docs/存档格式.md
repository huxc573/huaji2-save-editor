# 存档格式（逆向结论）

> 本文记录《画迹2：缘起凡尘》尝鲜版的**实测**格式结论。
> 所有结论都来自对游戏目录里实际字节的交叉验证，探针脚本见 `probes/`。

---

## 1. 引擎与目录

| 项 | 值 | 依据 |
|---|---|---|
| 引擎 | RPG Maker **VX Ace**（RGSS301） | `Game.ini` → `Library=System\RGSS301.dll` |
| 脚本入口 | `Data\main.rvdata2` | `Game.ini` → `Scripts=Data\main.rvdata2` |
| 存档 | `<游戏根>\save.rvdata2` | 实测 |
| 自动存档 | `<游戏根>\AutoSave\save00..29.rvdata2` | 实测，30 个槽位（`Config.ini` 的 `auto_save_max=100`） |
| 战斗日志 | `<游戏根>\Logs\Battle\<yyyy-mm-dd HH-MM-SS>\` | 实测 |
| 保护库 | `System\main.dll`（MPRESS 加壳，382,976 字节） | `Data\main.rvdata2` 里就一句 `qqeat` 调用 |
| 保护配置 | `Config.ini`（`md5=`/`auto_save_*`/`memory_*`）、`System\Game.md5`、`was.info` | 实测 |

`Data\main.rvdata2` 是**唯一没有加密**的 Data 文件（zlib 压缩的 Ruby 源码）：

```ruby
Win32API.new('System/main', 'qqeat', 'v', 'v').call
```

即：加密壳先把一切装好（解密真正的游戏脚本、打补丁），再跑游戏本体。

> `Data\Scripts.rvdata2`（291,000 字节）才是真正的游戏脚本，被加密。
> 注意 `main.rvdata2` 是 zlib 明文，但 `System.rvdata2` / `Actors.rvdata2` /
> `Map*.rvdata2` 等**全部是密文**。

## 3. 密文的容器形态

```
密文 = [8 字节定长头块] + ECB(明文按 8 字节分组)
密文长度 = 明文长度 + 8，且永远是 8 的倍数
```

实测（`probes/probe_15_format.py`，用 `main.dll` 自己加密 64 个 0 字节）：

```
明文 64 B  ->  密文 72 B
密文 = DD7F121CA5015619  8CA64DE9C1B123A7 ×8
                                    └─ 8 个 0 字节块 ecb 后完全一样
明文 4096 B -> 密文 4104 B
密文 = F15D0F286B65BD28  8CA64DE9C1B123A7 ×512
```

关键性质：

* **ECB**：$E(0^8) = \texttt{8CA64DE9C1B123A7}$ 重复 512 次 —— 相邻 3149 个
  相同密文块连续出现，CBC/流式都不可能（CBC 下同一明文块串不会产生同密文）。
* **确定性**：同一明文加密两次**逐字节相同**（无随机 IV / 盐）。
* **头块随内容与长度变化**：改明文第 0 字节会改头块；长度不同头块也不同 ——
  头块疑似"长度 / 校验"字段（未完全确认）。
* **分组密码是真算法**：把 38806 个块与最高频块比汉明距离，分布是
  `{6 字节:10, 7 字节:667, 8 字节:20496}`，**没有 1~5 字节**的近似块 ——
  说明块内充分混淆（不是逐字节替换），符合"正经的 64 位分组密码"。

所以：**不能靠猜明文去 XOR 反推，必须是拿到密钥状态或走 DLL。**

## 4. `System\main.dll` 的对外接口

MPRESS 加壳（节区 `.MPRESS1/.MPRESS2`），静态反汇编无效；
把 DLL `LoadLibrary` 之后 dump 内存即可拿到解壳代码（`probes/` 里已做）。

导出表（`probes/probe_03_dll.py` 输出，共 36 个）：

| 类别 | 导出 |
|---|---|
| 加解密 | `encryption_file` `decryption_file` `encryption_buff` `decryption_buff` `init_key` `dispose_key` |
| 校验/防护 | `get_md5` `get_hard_disk_character` `shield` `net_wrong_count` `init_debug` `qqeat` |
| 网络 | `http_request` `http_bytes` `http_upload` `get_qq` |
| 文件/系统 | `read` `readFile` `seek` `file_enum` `delete_file` `delete_dir` `dir_count` `get_fsp` `find_fsp` `select_file` `utf8_to_ansi` |
| 其它 | `screen_capture` `get_clipboard` `copy` `copy_img` `copy_text` `get_ttf_name` `call_input` `init` `test` |

### 4.1 调用约定（踩坑记录）

* 导出是 **stdcall**，`decryption_file(a, b, c)` 是 `ret 0xC` → 3 个参数；
  `encryption_buff(a, b)` 是 `ret 8` → 2 个参数。
* 导出的内部实现拿的是"指向参数槽的指针"，但**导出本身吃的是普通值**，
  所以从 C#/C 直接按 3 个 `char*` 调即可（`probes/xjhost32.cs` 已验证）。
* **参数必须是 UTF-8**：DLL 内部 `0x10DD` 会做 `UTF8(65001) → GBK(936)` 转换
  （常量 `0xfde9` = 65001，`0x3a8` = 936）。传 ANSI 的后果是中文路径
  **打不开文件、返回 0、不产生输出**——这个坑卡了很久。
* `main.dll` 是 **32 位**库，64 位 Python 不能 `LoadLibrary`，所以随包带
  `src/XJCodec32.exe`（C# 编译的 32 位宿主）中转。

### 4.2 实测可用的行为

```text
encryption_file(明文路径, 密文路径, 第三参数) -> 1      # 输出 = 输入 + 8 字节
decryption_file(密文路径, 明文路径, 第三参数) -> 1/0    # 上面结果的逆运算
```

* 自检（本工具加密→解密）**逐字节一致**（`tests/test_codec.py` 通过）。
* 第三参数会改变密文，但**不是口令**：任意取值都能自洽往返；
  已爆破 400+ 个候选（文件名、路径、md5、中文词、整数……）**没有命中**。

## 5. `was.info`（未加密）

269,568 字节，开头 `04 08 7B 02 81 01 49 22 0E …`。
从第 6 个字节起是**标准的** Ruby Marshal：

```
:offset => { "循环" => [20,35], "指打" => [21,35], "防微" => [20,35],
             "死亡" => [19,33], "攻击" => [51,39], "明法" => [56,66], … }
```

键是带实例变量 `@E = true` 的字符串（游戏中"名 → [a, b]"的对照表，疑似
保护系统自己的"名字 → 偏移"校验表，量很大，约 1.3 万条）。
开头 6 字节 `04 08 7B 02 81 01` 不符合标准 Marshal（`{` 后面的元素个数
应是 `07` 而不是 `02`），说明它不是普通的 Marshal 顶层对象，
**v0.1 未使用这个文件**。

## 6. 明文长什么样（待确认）

明文 100% 是 Ruby Marshal 4.8（RGSS301 / Ruby 1.9 语义）：

* 整数一律 `i` + `w_long`（不是 Ruby 1.8 的裸字节）；
* 字符串 `"` + 长度 + UTF-8 字节；
* `RPG::Table` 用 `u`（userdef）原样保存二进制块；
* 每个顶层对象**独立**编号，`@N` 不能跨对象引用。

VX Ace 的 `DataManager` 是把 header 和 data **分两次** `Marshal.dump` 到
同一个文件里，所以明文很可能是"**多个 Marshal 对象首尾相接**"——
`src/xj_marshal.parse_stream()` 就是按这个写的（会逐个重置链接表）。

> 直接证据：`Logs\Battle\*\Battle.bt2` 是明文，内容是
> `04 08 7B 0A 3A 0A 74 72 6F 6F 70 …`，即 `{:troop=>…, :rand=>…, :time=>…,
> :tips=>…, :current_he…}`，说明游戏自己写文件时用的就是标准 `Marshal.dump`。

## 7. 与《画迹1》的差异（重要）

| 项 | 画迹1（落日情缘） | 画迹2（缘起凡尘） |
|---|---|---|
| 引擎 | RMXP（RGSS102J/103J） | **VX Ace**（RGSS301） |
| 存档位置 | `Audio\BGM\sy.ogg`（伪装成音乐） | **`<根>\save.rvdata2`** |
| 容器 | `0D 0F 3E 03` + 长度 + zlib(密文) | **没有容器**，直接是密文 |
| 加密库 | `tp.dll` 导出 `DS1/DS2`，口令 `"xjy.11"`，**位置相关**（同明文块不同位置密文不同） | `System\main.dll`（QQEat，MPRESS），**ECB 位置无关**，无口令 |
| 解壳 | 不需要 | 需要（MPRESS） |

⇒ **两代的加密不通用**，huaji1 的 `TP.dll` 路线在画迹2 上无效
（`probes/probe_08_compare.py` 的对比可复现）。
