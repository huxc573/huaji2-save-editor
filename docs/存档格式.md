# 存档格式

> 《画迹2：缘起凡尘》[尝鲜版] —— RPG Maker VX Ace（RGSS301 / Ruby 1.9 Marshal 4.8）
> 本文所有结论都是**实测**得到的（脚本见 `tools/`）。

## 1. 文件在哪儿

| 文件 | 说明 |
| --- | --- |
| `<游戏根>\save.rvdata2` | 手动存档 |
| `<游戏根>\AutoSave\save00..29.rvdata2` | 自动存档（`Config.ini` 里 `auto_save_max=100`） |
| `<游戏根>\Data\*.rvdata2` | 数据库（System / Actors / Items / MapNNN …） |
| `<游戏根>\Data\Scripts.rvdata2` | 游戏脚本本体（被加密藏起来了） |
| `<游戏根>\Data\main.rvdata2` | 脚本入口，**明文**，内容只有一句 `Win32API.new('System/main','qqeat','v','v').call` |
| `<游戏根>\System\Game.md5` | 被加密的完整性清单（只含 Game.exe 和 main.dll 的 md5） |
| `<游戏根>\was.info` | **明文** Marshal，与存档逻辑无关 |

## 2. 加密：谁在加、用什么密钥

加密由 `System\main.dll` 的导出完成：

```
decryption_file(输入路径, 输出路径, 密钥)  -> 0/1     (stdcall；三个参数都是 UTF-8 char*)
encryption_file(输入路径, 输出路径, 密钥)  -> 0/1
```

**第三个参数就是密钥字符串。** 密钥不对时 DLL 不报错，而是**写出 0 字节的空文件** ——
所以"输出非空 = 命中"这个判据非常干净（爆破时唯一的信号就是它）。

逆向出来的三个密钥：

| 密钥 | 用途 |
| --- | --- |
| `761205` | `Data\*.rvdata2` 数据库、`System\Game.md5` |
| `imoutogadaisuki` | `Data\Scripts.rvdata2`（脚本本体） |
| `tiyan_version` | 存档 `save.rvdata2` / `AutoSave\*.rvdata2` |

* `761205` / `imoutogadaisuki` 藏在 main.dll 解壳镜像 RVA `0x118850` 附近的常量区；
* `tiyan_version` 写在游戏脚本的 `Config::File::SAVE_FILE_PASSWORD` 里。

密文形态（任意明文实测）：

* 密文长度一定是 8 的倍数；
* 同一明文的相同 8 字节块 → 相同密文（ECB，无随机量、无 IV）；
* 密钥错了输出的"垃圾"也一样是 8 字节一组。

## 3. 解密后的明文：两个 Marshal 对象拼在一起

游戏是这样写档的（脚本里 `DataManager.save_data`）：

```ruby
Marshal.dump(make_save_header, file)     # { :temp => nil }
v = make_save_contents                   # 一个 Hash
Marshal.dump(v, file)
```

所以明文 = `04 08 {...}` + `04 08 {...}`；**每个顶层对象各自带 04 08 头，
各自从 0 开始算对象编号/符号编号**，解析时必须每个对象重置链接表。

`make_save_contents` 的 11 个键（顺序固定）：

```
:system  :timer  :message  :switches  :variables
:self_switches  :actors  :party  :troop  :map  :player
```

实测 `save.rvdata2`：密文 310448 字节 → 明文 310437 字节 → 解析结束位置正好 310437。
（另一台/另一次存档实测 312404 字节，同构。）

### 各分区的类与关键字段

| 分区 | 类 | 有用的字段 |
| --- | --- | --- |
| `:system` | `Game_System` | `@seeds`（Hash；`[:shield]` 是防作弊种子）、`@save_count`、`@cheated`、`@keyword`、`@security`（物品计数校验，见 §7） |
| `:switches` | `Game_Switches` | `@data` = Array（下标 = 开关编号） |
| `:variables` | `Game_Variables` | `@data` = Array（下标 = 变量编号） |
| `:actors` | `Game_Actors` | `@data` = Array（下标 = 角色 id，元素是 `Game_Actor`，带 `@babies` 召唤兽） |
| `:party` | `Game_Party` | `@gold`（`Lock` 包装，界面叫“存银”）、`@actors`（角色 id 数组）、`@items`/`@weapons`/`@armors`（Hash：格子号 => [对象, 数量]）、`@steps`、`@warehouse_page` |
| `:map` / `:player` | `Game_Map` / `Game_Player` | 地图 id、坐标等 |

`Game_Actor` 的字段：`@name`、`@level`、`@exp`（是 Hash）、`@hp`、`@mp`、`@skills`、`@equips`、`@babies` 等。

## 4. 防作弊：`Lock`

关键数值（金钱等）不是裸整数，而是 `Lock` 对象：

```ruby
class Lock
  def initialize(v)
    @value = v
    @master = get_encryption(@value)
  end
  def seed; $game_system.seeds[:shield]; end
  def get_encryption(v); v * 91 + 45 + seed / 800; end   # Ruby 里 / 是整除
  def show
    if get_encryption(@value) != @master
      msgbox '游戏异常！'
      exit                        # ← 直接改 @value 就会踩这里
    end
    return @value
  end
  def +(other); self.class.new(show + other); end         # 四则运算都会重建 Lock
end
```

所以"改钱"的正确做法是：

```
@value  := 新值
@master := 新值 * 91 + 45 + $game_system.seeds[:shield] / 800     # 整除
```

`src/xj_save.py` 的 `set_gold()` 会自动同步；`repair_locks()` 会扫全档修所有 Lock。

> 本机实测：`seeds[:shield] = 237599985163622727515788549406877775289`，
> 原档 `@gold @value = 1164` → `@master = 296999981454528409394735686758703188`，
> 用上面的公式正好算得出来 —— 说明公式复刻无误（`tools/test_save_layer.py` 会验证）。
>
> 另外注意 `@master` 是 **Bignum**（大整数），写回时要按 `l` 类型编码。

## 5. 背包：4 页×20 格

`Game_Party` 里三个 Hash：`@items`（道具）/ `@weapons`（武器）/ `@armors`（防具），
**key 是“格子号”，不是物品 id**：

```
格子号 = 页号 * 20 + 格内序号          页 0..3，格 0..19（对应游戏道具菜单的 4 页）
@items[格子号] = [ 物品对象, 数量 ]     物品对象是从 Data\Items.rvdata2 复制的
                                      （@id 才是真正的物品 id）
```

* 空格子：key 不存在，或 value 是 `nil`。
  清空格子用“置 nil”而**不是删 key**：不改变对象个数 → 不会踩 `@N` 编号错位的坑。
* 加物品：从 `Data\<kind>.rvdata2` 里克隆模板对象。
  模板只有 19 个 ivar，存档里的实物还多了游戏自己加的 5 个：
  `@result_note` / `@attr` / `@update` / `@new` / `@transaction_code`，
  新建时要一并补上（`@transaction_code` 是随机大整数）。
* 仓库另有页号：`@warehouse_page`（0..3）。
* 上限：`Config::Game::MAX_GOLD = 30000000`、物品单格上限 99（工具里放宽到 99*99）。

## 6. 召唤兽：`Game_Baby` / `Game_Baby_Attr`

每个角色（`Game_Actor`）有一个 `@babies`（数组），元素是 `Game_Baby`；
资质与五维放在中文 ivar 的 `Game_Baby_Attr` 里（和角色的 `Game_Actor_Attr` 一个路子）。

| 字段 | 含义 | 上限 |
| --- | --- | --- |
| `@level` | 等级 | 65 |
| `@hp` / `@mp` / `@tp` | 气血 / 魔法 / 灵力 | — |
| `@exp` | 经验 | — |
| `@life` | 寿命 | 12000 |
| `@loyalty` | 忠诚 | 100 |
| `@growth` | 成长 | — |
| `@attr` | `Game_Baby_Attr`：六项资质 + 五维 | — |

预设按钮（满级/回满/忠诚满/寿命满/资质+100/五维+10）都是直接改这些字段。

## 7. 物品计数校验：`Change`（AES）

`:system` 下的 `@security[:items]` 是一个 Hash：**物品 id => `Change` 对象**。

```ruby
class Change
  def initialize(code)
    @code = code                     # 一段 Ruby 片段，当场算出“应该是多少”
    @value = @code.split('').map{|c| encrypt(c) }   # 数字逐位加密，存成字符串数组
  end
end
```

* `@value` 的每一项是 **1 位十进制数字的 AES-128-ECB 密文**（存成 16 进制字符串）。
  密钥写死在游戏里：**`admin_1941344749`**（PKCS#7 填充，密文 16 字节 = 32 个 hex 字符）。
  `src/xj_aes.py` 是纯 Python 实现（不依赖 pycryptodome），
  `encrypt_digit('7')` / `decrypt_digit(hex)` 单字符对单字符。
* 整数 = 各位数字解密后拼起来（`["a3..","9f.."]` → `"79"` → `79`）。
* `@code` 是游戏自己写的：
  `proc{|i| $game_party.item_number(i) + $game_party.item_number(i, $game_party.warehouse)}.call(物品id)`
  所以“校验值”其实是**累计获得数**。
* 游戏只给 `RPG::Item` 记账（脚本里直接 `return` 掉了 Weapon/Armor），
  而背包里三种对象是混装的 ⇒ 算总数时要**按 `@id` 分类过滤**。
* 改背包后必须重算：`GameEditor.sync_security_item(id)`；
  原本没条目的（游戏还没发过这件东西）就照上面的模板新建一个。

## 8. 周期检查：`$jiance` 与 `@cheated`

游戏每 300 帧（`Graphics.frame_count % 300 == 0`，约 5 秒）扫一次存档：

```ruby
if Graphics.frame_count % 300 == 0 and $game_system and !$game_system.cheated
  # 逐项比对：存银上限、仓库页号、角色等级/五维总点、召唤兽等级……
  # 不对就：$game_system.keyword << keyword
  #         $game_system.cheated ||= Graphics.frame_count
```

另外 `Change#inspect`（调试/内省）也会比对 `@code` 的期望值与实存值，
不一致同样置 `@cheated = Graphics.frame_count`。

`@cheated` 是个**帧计数定时炸弹**：

```ruby
if $game_system.cheated
  v = Graphics.frame_count - $game_system.cheated
  if v > 60*60*25-123        # = 89877 帧 ≈ 25 分钟（相对于记下时的帧数）
    msgbox "存档异常！#{...}"
    exit
```

`Graphics.frame_count` 每次启动都从 0 开始，所以一个 `@cheated = 134700` 的存档，
本次连续玩到第 224577 帧（约 62 分钟）就会弹「存档异常」退出；
而且只要 `@cheated` 非 false，上面的周期检查就**不再跑了**（`!$game_system.cheated`）。

⇒ 工具里「体检」会把它列出来，「清除作弊标记」把它置 `false`。
清零会重新武装周期检查，所以同时要把其他几项（存银/等级/五维/召唤兽等级）
都改回合法值。

## 9. Marshal 解析的坑（都踩过）

| 坑 | 现象 | 解法 |
| --- | --- | --- |
| 非 ASCII 符号外面包了一层 `I` | 写作 `I :@体质 { :E => true }`；只认 `:`/`;` 会在中文实例变量名上报"坏符号 0x49" | `read_symbol()` 递归处理 `I` 前缀 |
| `c` / `m`（类 / 模块对象）**也占对象编号** | 不登记的话后面所有 `@N` 链接整体错一位，最后报"链接越界" | 登记 `ClassNode` / `ModuleNode` |
| `I` 包装**不额外占**编号 | 内层对象已经登记过，重复登记会错位 | `I` 节点不 `register()`，只登记内层 |

另外还要支持：`}`（带默认值的 Hash）、`C`（String/Array/Hash 的子类）、
`u`/`U`（自定义序列化对象）、`l`（Bignum）、`f`（Float）。

排查手法：严格模式下（`xj_marshal.STRICT_LINKS = True`）
* 校验 `@N` 链接不越界；
* 校验类名长得像 Ruby 类名；
* 校验实例变量名不是控制字符；
* `tools/parse_diag.py` 会把出错时的**递归调用链**（每层容器起始偏移）打出来，
  一眼看出是被哪一层套娃吃掉了。

## 10. 写回

* 改**标量**：只重编码那一个字段的 `[start, end)` 字节区间 —— 不影响任何 `@N` 链接。
* 改**容器/成员数**：`doc.mark_structural()` → `xj_marshal.serialize_doc(objects)`
  **整档重写**（带符号表，17/17 与原明文逐字节相同），自动重新编号 `@N`。
  （旧接口 `xj_edit.serialize_tree` 会把链接展开成独立副本，现在不用了。）
* 写文件：先 `parse_stream(新明文)` 自检，能解析才加密覆盖，并自动留
  `*.bak.<时间戳>` 备份。

## 11. `Data\*.rvdata2` 数据表（加密的，但能解）

`Data` 目录里的 `.rvdata2` **和存档一样被 `System\main.dll` 加密**，
只是密钥不同：全部用 **`761205`**。`src/xj_db.py` 解密 + 解析后转成 CSV。

| 表 | 类 | 行数 | 默认转 |
| --- | --- | --- | --- |
| `Items` | `RPG::Item` | 300 | ✅ |
| `Weapons` | `RPG::Weapon` | 400 | ✅ |
| `Armors` | `RPG::Armor` | 300 | ✅ |
| `Skills` | `RPG::Skill` | 320 | ✅ |
| `States` | `RPG::State` | 120 | ✅ |
| `Actors` | `RPG::Actor` | 300 | ✅ |
| `Classes` | `RPG::Class` | 300 | ✅ |
| `Enemies` | `RPG::Enemy` | 700 | ✅ |
| `Troops` | `RPG::Troop` | 310 | 可选 |
| `CommonEvents` | `RPG::CommonEvent` | 100 | 可选 |

不转的：`Map*`（几十张地图，看了也没用）、`System`、`Scripts`、
`Tilesets`、`Animations`、`main`。

根节点是 `Array`，下标就是 id（`nil` 的位置跳过）。几处嵌套结构：

* `@effects`：`RPG::UsableItem::Effect`，`code` 11/12/13 HP·MP·TP，(21/22 附加·解除状态，
  31~34 强化弱化，41 特殊，42 成长，43 习得技能，44 公共事件；
* `@damage`：`RPG::UsableItem::Damage`（`type`/`formula`/`variance`/`critical`/`element_id`）；
* `@features`：`RPG::BaseItem::Feature`（`code`/`data_id`/`value`）；
* `@params`（武器/防具/敌人）是 8 个数（最大HP/最大MP/攻/防/魔攻/魔防/敏/运），
  武器的 `@params` 是 `Table`（自定义序列化 `u`），只报字节数；
* `@learnings`（职业）是 `RPG::Class::Learning`（`level`/`skill_id`）；
* `@actions`（敌人）是 `RPG::Enemy::Action`（`skill_id`/`rating`…）；
* `@drop_items` 是 `RPG::Enemy::DropItem`（`kind` **0=无** 1=物品 2=武器 3=防具、
  `data_id`、`denominator`）；本作敌人全部 `kind=0`（没配掉落），所以 CSV 里显示“无”。

导出时用 **`utf-8-sig`**（带 BOM），Excel 双击不乱码；嵌套字段由
`fmt_effects` / `fmt_damage` / `fmt_features` / `fmt_params` / `fmt_learnings` /
`fmt_actions` / `fmt_drops` / `fmt_members` 翻成人话。

## 12. 复现命令

```bat
python tools\decrypt_all.py       :: 用正确密钥把各文件解密到 tools\_plain\
python src\xj_save.py             :: 读存档概览 + 防作弊校验状态
python src\xj_save.py repair      :: 一键修好所有 Lock 并写回
python src\xj_db.py               :: 列出 10 张 Data 表 + 行数
python src\xj_db.py --out csv     :: 数据表转 CSV
python tools\probe_guard.py       :: 体检逐项打印（看哪个超限）
python tools\verify_all.py        :: 所有明文文件能否完整解析 + 重写自洽
python tools\test_roundtrip.py    :: 整档重写是否字节一致
python tools\test_semantic_equal.py :: 重写前后语义树是否等价
python tools\test_game_layer.py   :: 背包/召唤兽/计数校验/体检
python tools\test_save_layer.py   :: 语义层与防作弊修复的回归测试
python tools\test_db_csv.py       :: 数据表解析 + CSV 导出回归测试
python tools\test_dist.py         :: 打包好的 exe 能不能独立跑
python tools\run_tests.py         :: 一键全部回归
```
