# 开发指南

给以后改这个仓库的人（包括未来的我）。

> **本文是内测版 V2.201 分支（`beta`）。**
>
> 绝大部分内容（命令、模块职责、「最容易写坏存档的四件事」、发版流程）
> **与游戏版本无关，照旧能用**。但有两处必须先知道，否则会踩：
>
> 1. **加密不是 `main.dll` 做的** —— V2.201 的 `main.dll` 加壳后导不出

>    三个功能各有一套**纯 Python** 实现：
>    `src/save_v201.py`（存档 AES-128-ECB+Zlib）、

> 2. **游戏上限差2.5 倍** —— 等级 **155**（不是 60）、金钱 **9,999,999,999**
>    （不是 30,000,000）、仓库**12 页**（不是 3）。在 `src/fieldnames.py`。
>    ⚠ 用尝鲜版的值会让工具**主动把合法值压回去**。
>
> `docs/逆向过程.md` 是**尝鲜版**的过程记录，结论不适用，但方法论可参考。

## 1. 环境与命令

```powershell
# 依赖：Windows + Python 3.10+ + .NET Framework 4.x（自带 csc.exe），无第三方 pip 包
#       打包 exe 额外需要一个装了 PyInstaller 的解释器
#       ⚠ ..\.venv（Python 3.14）已损坏（base 解释器被 uv 清掉）→ 临时用系统 Py3.12 打包：
#         XJ_PY=D:/Dev/Python/Env/Python312/python.exe python tools/pack_only.py
python tools/build_host.py        # 编译 src/native/XJCodec32.exe（改动 native/codec32.cs 后必做）
python tools/run_tests.py         # 一键跑全部回归（19 组，含 dist / bundle_db，两者要先打包）
python tools/run_tests.py gui     # 只跑名字含 gui 的那几组
python src/huaji2_save_editor.py           # 开界面
python tools/build.py             # 打包 exe（含自检）
python tests/test_dist.py         # 只验证 dist\ 里的 exe 能独立跑
python src/datatables.py --out csv     # Data 数据表 → CSV
```

⚠ 本工作区路径含 `!` `【】[]` 与中文，**在终端里跑上面这些命令时要特别小心**：

* `run_in_terminal` 会把命令包进 `powershell.exe -Command "…"`，双引号会被吃掉，
  含 `!`/中文的路径经它一传就变形（`【尝鲜版】` → `` `[尝鲜版`] ``）。
  可行的写法是 `Set-Location -LiteralPath '<仓库>'` 先切目录（用单引号），
  然后一律用**相对路径**：`cmd /c ""D:\Dev\Python\...\python.exe" tests\test_gui.py"`。
* PS 5.1 里相对路径 + `-LiteralPath` 在“当前目录含 `[]`”时会报“对象不存在”，
  删文件用 `python tools\re\rmfile.py <相对路径>`。
* 测试脚本要弹窗的地方（GUI）必须把 `huaji2_save_editor.messagebox` 换成记录函数，
  否则隐藏窗口上的模态框会把测试挂死（看不到、点不了）。

找不到游戏目录时：`$env:XJ_GAME = "<游戏根>"`（含 `Game.exe` 的那层）。

### 目录结构（2026-09-20 整理后的口径）

```
src\                程序本体
  huaji2_save_editor.py   主程序（以项目名命名）
  *.py（无前缀）          各层模块：doctree / save / game / codec / marshal_ruby …
  tables\                 游戏常量表（自动生成，别手改）
```

## 2. 数据流

```
save.rvdata2 (密文)
   │  codec.decrypt_file()
   │     └─ subprocess → src/native/XJCodec32.exe → System\main.dll!decryption_file
   ▼
明文 Marshal 字节流
   │  marshal_ruby.parse_stream()      （多个顶层对象首尾相接，逐个重置链接表）
   ▼
Doc.objects: [{'head','node','links'}]
   │  界面：huaji2_save_editor 建树 / 改值 → patchwriter.PatchEngine.set_scalar()
   │        （等宽标量值 → 区间补丁）
   │  结构性修改（背包增删物品、新建 Change 对象…）→ doc.mark_structural()
   │        → marshal_ruby.serialize_doc(objects) 整个文档重写（带符号表，字节级一致）
   ▼
patchwriter.PatchEngine.apply() 或 marshal_ruby.serialize_doc()   → 新明文
   │  marshal_ruby.parse_stream() 解析**就一次**（解析不过就拒绝写）
   │      同一份解析结果接着做「重序列化 == 原字节」自检，并直接当新的 objects
   │  codec.encrypt_file()
   ▼
写回 save.rvdata2（原文件自动备份为 .bak.<时间>）
```

## 3. 各模块职责

| 模块 | 职责 | 注意 |
|---|---|---|
| `paths.py` | 定位游戏目录 / `main.dll` / 存档 | **不要用 glob**（路径含 `【】[]`，`[` 会被当字符类） |
| `codec.py` | 驱动 `XJCodec32.exe` | 只通过进程通信，不在本进程加载 DLL；打包后宿主在 exe 旁边或 `dll\` |
| `native/codec32.cs` | 32 位宿主 | 字符串参数**必须 UTF-8**；路径要用绝对路径 |
| `marshal_ruby.py` | Ruby Marshal 4.8 | 节点带 `start/end` 字节区间，是"区间补丁"的基础；`serialize_doc()` 是**字节级重写**（带 symtab） |
| `patchwriter.py` | 区间补丁 | 标量走 `set_scalar`（按节点类型赋值，`assign_value`）；**长度变化**的修改走 `serialize_doc` |
| `doctree.py` | 语义层 Doc | `structural` 标记；写回前会再解析一次，解析不过就不写 |
| `save.py` | 存档语义层 | `SaveDoc(doc=…)` 必须把界面的 Doc 传进来，否则改的是另一份内存副本 |
| `aes.py` | AES-128-ECB（纯 Python） | 只用来读写 `Change` 里的物品计数校验；密钥 `admin_alskmcndfj`（游戏 V2.201 实际值） |
| `game.py` | 游戏层（存银/背包/经验/召唤兽/防作弊） | 改背包后必须 `resync_security()` 或逐个 `sync_security_item()`，否则物品计数校验对不上 |
| `nodetext.py` | 节点 → 人能看懂的文字 | `key_label()` / `note_for()`；`[None]` 就是没走这里造成的 |
| `fieldnames.py` | 全部中文注释 / 上限常量 | `SWITCH_NAMES` / `VARIABLE_NAMES` 是游戏自己写在脚本里的名字 |
| `datatables.py` | `Data\*.rvdata2` → CSV | 表定义在 `TABLES`（列 = `(中文表头, 取值说明)`），加列只改这一处 |
| `tables\` | 游戏常量表（`exp` / `sect` / `baby_aptitude`） | **全部自动生成，别手改**；改跑 `tools/gen_*.py` |
| `huaji2_save_editor.py` | 界面（9 个页签） | 不改数据，只调 Doc / SaveDoc / GameEditor；数据树是**懒加载**的 |

### 界面里的几个约定

* `App(root, save_path=None)` —— 不是 `Tk` 子类，`App` 只包住一个 `root`；
  关窗口要 `root.destroy()`。
* 页签 Frame 都存成属性（`tab_quick` / `tab_tree` / `tab_actor` / `tab_party` /
  `tab_baby` / `tab_switch` / `tab_db` / `tab_help` / `tab_log`），方便测试当锚点。
* `refresh_panels()` 把 7 个面板逐个刷，**每步单独 try**：一个面板出错不能连坐
  “全部解析数据”。
* 数据树：`CHILD_LIMIT`（300）配合 `<<TreeviewOpen>>` → `_fill_children()`；
  搜索走的是模型层（`_walk_search`，不进 Treeview），命中后用 `_reveal()` 展开路径。
* 所有 Tk 回调的未捕获异常走 `root.report_callback_exception = _tk_exception`
  → 写 `error.log` + 弹框 + 状态条 （打包成 exe 后不然就是“点了没反应”）。
* `App._guess_save()` 会读 `~/.huaji2_save_editor_last.txt`（上次打开的文件）。
  **自检时别被它带偏**：`selftest_lines()` 按 `XJ_SAVE` → 游戏目录 save.rvdata2
  的顺序重载一遍。
* **Treeview 里塞不了控件**（角色页的 `ttk.Checkbutton` 那套搬不进去）。
  要「勾选框」就用**字形 + 点第一列**：表头写「已学」、值放 `■`/`□`，
  再 `tv.bind("<Button-1>", ...)` 里 `identify_column(event.x) == "#1"` 才切、
  切完 `return "break"`（别让选中跟着跳）。见 `SkillManager.on_click`。
  ⚠ **微软雅黑没有 ☑/☐/✓/☒/⬛ 这些字形**（上屏是豆腐块，`font.measure` 也测不出来，
  得拿私用区码位 `\ue123` 比对才看得出）。能用的是：`■ U+25A0` / `□ U+25A1` /
  `● ○ ◆ ◇ √ × ╳`。已学＝`■`、没学＝`□`。
* **`pack` 是「先来先分地盘」**：`side="right", fill="y"` 的 Scrollbar 直接 pack 进
  整页 frame，会被撑满整页高、贴到窗口最右（召唤兽页 2026-10-04 的毛病）。
  正确做法是**先包一层只有列表那么高的子 frame**，再在它里面 pack 滚动条 + 列表。
* **「归属」这类一列多用的情况，要说清优先级**：目前是**分段 > 门派**
  （门派技能里 `index 10` 的「上古××」秘技两头都占，按分段算才能让
  「筛某一段 → 列出来的行标着那一段」成立）。见 `SkillManager.own_text` / `own_ok`。

## 4. 加一个新功能的一般步骤

1. **先确认格式**：写个 `probes/probe_XX_*.py`，把结论落到 `docs/存档格式.md`。
   不要凭猜改写存档 —— 一个字节错位就会让游戏报
   `TypeError: cannot convert Array into String`，而且**字节层看不出来**。
2. **在 `doctree.py` 里加语义方法**（例如 `set_gold`），内部用
   `patchwriter` 的补丁接口，不要直接拼字节。
3. **写测试**：`tests/` 下加一条，样本优先用游戏自带的明文文件
   （`Logs\Battle\*\Battle.bt2`），或在临时目录里造。
4. **界面**：在对应页签加控件，调 `Doc` 的方法。
5. **更新** `README.md` / `CHANGELOG.md`。

## 5. 最容易写坏存档的四件事

1. **Marshal 对象链接 `@N`**
   Ruby 存盘时同一个对象第二次出现只写一个编号。动了某个对象内部的成员数量，
   后面所有编号都会错位。⇒ 结构性修改一律走
   `marshal_ruby.serialize_doc(objects)` 重新编号（写字节级重写）；
   能等宽的才做**标量区间补丁**。
2. **非 ASCII 符号只在“定义”处包装**
   `I` 类型里写符号：`I :名字 <e> :E T`（`e` = UTF-8）；
   后续引用只能写裸 `;N`。给“符号定义”加 `I` 头、给链接也加 `I` 头，
   都会让字节数和 Ruby 的解释完全变样（见 `emit_sym` / `sym_body`）。
3. **改完必须再解析一次**
   `Doc.save()` 里 `M.parse_stream(new)` 就是这道闸；解析不过直接抛异常、不写盘。
   ⚠ **只解析一次**：解析器是纯函数，同一份 `new` 解析出来的树等价；
   再解析一遍纯属白花（46 万字节的档一次约 0.5s，见 §7）。
4. **`RPG::Table`（`u` userdef）里的二进制块**
   当成不透明数据原样保留，**不要解码也不要重排**。

**校验口径**：`tests/test_roundtrip.py` 要求“解析 → 重写”与原始密文解密后的明文
**逐字节相同**（17/17）；`tests/test_semantic_equal.py` 要求语义树等价（39/39）。
改了 `marshal_ruby.py` 两个都要跑。

## 6. 打包成 exe

```powershell
python tools\build.py              # 编宿主 + 准备 dist + PyInstaller + 临时目录自检
python tools\build.py --dll-dir    # 宿主放进 dist\dll\（依赖多的时候用）
python tools\build.py --nopack     # 只编宿主、只准备 dist
python tests\test_dist.py          # 单独重跑 exe 自检（会打印 selftest_result.txt）
python tools\check_pack.py         # 发版前：验「缺宿主就不能用」的两种情形（A 组 NG / B 组 OK）
```

要点：

* 解释器：优先 `$env:XJ_PY`，否则找仓库旁的 `..\.venv\Scripts\python.exe`，
  再否则用当前解释器；**必须装了 PyInstaller**。
* tcl/tk 的脚本库不会自动收集，`tcl_data_args()` 手动 `--add-data`。
* `--onefile --windowed`，产物 `dist\画迹2存档工具.exe`（约 13 MB，**不带版本号**）。
* **`XJCodec32.exe` 必须和主 exe 挨着**（或放 `dll\`、`bin\`、`依赖DLL\`）——
  它**不在** onefile 里（`codec.host_candidates()` 是在 exe 所在目录找的），
  自检里会报“32 位宿主”是一项。**少了它就弹「打开失败」，整个工具都用不了。**
* **`main.dll` 绝对不打进去**：有版权、而且它会联网上报；
  只让 32 位宿主去游戏目录加载它。
* 自检 = 把整个 dist 拷到**临时目录**跑 `XJ_SELFTEST=1`，
  并清掉 `PYTHONHOME/PYTHONPATH/VIRTUAL_ENV`（不然 PyInstaller 引导会失败）；
  因为临时目录里找不到游戏，会把 `XJ_GAME`/`XJ_SAVE` 喂给它。
  跑完读 `selftest_result.txt`，最后一行必须是 `结果: OK`。
* ⚠ `main()` 的自检分支里**必须先 `app.cancel_auto_load()` 再 `root.update()`**：
  `App.__init__` 排了一个 200ms 的自动载入，它会自己去 `load()`；缺宿主时
  `load()` 弹的是**模态**「打开失败」，无人值守的自检没人点 → 进程挂死、
  结果文件根本写不出来。这是**竞态**（时有时无），2026-09-30 在
  `tools/check_pack.py` 的「只拷 exe」一组里实测到，别靠运气。

### 发行包 = 一个 zip，别散着挂附件（2026-09-30）

`pack_zip()` 把 `ZIP_MEMBERS`（主 exe + `XJCodec32.exe` + 使用说明）打成一个
`huaji2-save-editor-vX.Y.Z.zip`，`RELEASE_ASSETS` 里**只留这一个**。

原因（画迹1 踩过、画迹2 也一样）：以前挂 exe / USAGE.txt / XJCodec32.exe 三个附件，
**总有人只下主程序**，然后报「打不开 / 缺少依赖」。画迹1 那边漏下的是
`TP.dll`/`Socket.dll`（宿主 `DllImport` 走系统搜索路径），v1.4.0 改成发 zip。

实测证据（`tools/check_pack.py`，把 dist 的 exe 单独拷进临时目录跑官方自检）：

| 拷进临时目录的 | 自检结果 |
| --- | --- |
| 只有 exe | `32 位宿主: 未找到（改不了存档！）` / `未加载存档` / `结果: NG` |
| exe + `XJCodec32.exe` | `结果: OK`（5 角色 / 背包 35 件 / 召唤兽带门派后缀） |

⚠ 画迹2 **不需要兄弟 DLL**：`src/native/codec32.cs` 用
`LoadLibraryExW(绝对路径, LOAD_WITH_ALTERED_SEARCH_PATH)` + `GetProcAddress`
载游戏的 `System\main.dll`，没有 `DllImport` 兄弟库 —— 画迹1 的 `TP.dll`/`Socket.dll`
那一类问题在画迹2 结构上不存在。

## 7. 保存这条路的耗时（改之前先量）

2026-09-27 实测（真档 46 万字节 / 5 个角色，"点保存"一度要 6.9s）：

| 段落 | 改前 | 改后 | 怎么改的 |
| --- | --- | --- | --- |
| `_pre_save_guard` → `anti_cheat_report` | 0.92s | 0.26s | `codec.machine_id` 加进程内缓存 |
| `doc.save()` | 3.84s | 1.51s | 3 次 `parse_stream` 减成 1 次（§5 第 3 条） |
| `refresh_panels()` | 1.98s | 0.65s | 复用体检表 + `machine_show` 走缓存 |
| **合计墙钟** | **6.89s** | **1.90s** | |

三个结论：

* **`subprocess` 起 32 位宿主一次约 0.3s** —— 保存路径上它会被问 3 次（存盘前体检 /
  概览页 / 机器码页）。所以 `machine_id` 一律走 `codec.machine_id()` 的进程内缓存；
  只有用户**显式**点「读本机机器码」才传 `refresh=True`。
* **一次保存只该算一遍体检表**。`save_save()` 把 `_pre_save_guard()` 算好的 rows
  透传给 `refresh_panels(guard_rows=…)` → `fill_info` → `guard_check`；
  没改动数据，两份内容本来就是一样的。（auto-fix 跑过就传 `None` 让它重算。）
* 量的时候**别用 `doc.save()` 里那段自检**当基准 —— 要先单独量
  `serialize_doc` / `parse_stream` / `encrypt_file`，不然只会看到一坨 3s。
  探针：`_tmp/probe_save_time.py`、`_tmp/probe_save_parts.py`、`_tmp/probe_save_inside.py`。

## 8. 平台坑（Windows + 中文/特殊字符路径）

* 终端/脚本里路径一律用绝对路径 + `-LiteralPath`；
  `Set-Location`/`cd` 对含 `[]` 的路径会失败。
* PowerShell 5.1 控制台是 GBK：Python 里 `print` 中文/符号会 UnicodeEncodeError；
  探针统一 `sys.stdout.reconfigure(errors='replace')` 并**写文件再读**。
* `Start-Process -FilePath` 遇 `[]` 当通配符 → 用
  `[System.Diagnostics.Process]::Start($psi)`。
* 旧 exe 被占用导致 csc 写不进去 → 换输出名或先 `Stop-Process`。

## 9. 名字从哪来（内置名字表）

界面里每一个名字（技能 / 物品 / 武器 / 防具 / 召唤兽 / 职业）本来都是**运行时**去
游戏目录读 `Data\<Key>.rvdata2` 拿的：`XJCodec32.exe` 解出来 → 解析 Marshal。
这一步在别人的机器上可能失败 —— 工具没放在游戏目录里、游戏版本对不上、杀软拦了、
或者内测版 V2.2 的解密被绑进授权链（见 `【画迹2】内测版\!Tools\V2.2研究报告.md`）。

于是有一份**内置快照** `src/tables/db_table.py`（由 `tools/gen_db_table.py` 生成，
`--check` 只校验）：

```
NAMES            {表键: {id: @name}}          Skills / Items / Weapons / Armors / Actors / Classes
DESCS            {表键: {id: @description}}
CLASS_LEARNINGS  {职业 id: [[等级, 技能 id], ...]}   ← 天生技能
```

取名字的口全在 `datatables` 里，调用方**不需要**知道自己用的是哪一路：

| 函数 | 用途 | 读不到游戏目录时 |
| --- | --- | --- |
| `name_map(key)` | id → 名字（界面到处在用） | 整表退回内置 |
| `desc_map(key)` | id → (名字, 说明)（悬浮提示 / 技能说明框） | 整表退回内置 |
| `class_learnings(cid)` | 职业天生技能 | 退回内置 |
| `builtin_rows(key)` | [(id, 名字, 说明)]（背包模板列表兜底） | — |
| `names_source(key)` | 这次用的是哪一路（自检/排查用） | — |

**优先级：游戏目录优先，内置兜底。** 读得到游戏目录就用它（跟「物品模板 / 克隆」
同源、也最跟得上游戏版本）；读不到才退回内置，两条路都拿不到就是空 / `?`，
**永不抛异常**。⚠ 这一点跟画迹1 相反（画迹1 是内置优先）——
画迹1 那边内置表覆盖的是它**全部**名字来源，而画迹2 的模板克隆（`make_item`）
仍然依赖游戏 Data，名字跟模板必须同源，否则会出现「名字说 A、克隆出来的是 B」。

当时为什么不做成「内置优先」：游戏更新后内置快照会过期，
而**给错名字比给 `?` 更糟**。

### 内置表救不了的地方（无数据表时仍然是降级，不是"满血"）

* `GameEditor.make_item()`：从 Data 模板**克隆整件物品**写进背包 —— 要完整节点，
  内置表只有名字。所以「背包 → 添加物品」在无 Data 时不能用（会弹提示）。
* `Babies.candidate()` / `config()`：要 `@note`、`@initial_level` 等模板字段。
  **「新增召唤兽」在无 Data 时列不出候选项。**
  （`itemattr` 的蛋池不再依赖 `@note` —— 它读 `tables/baby_aptitude.py` 的真值。）
* 「数据表 (CSV)」页：转的是整份数据，`rows()` 照旧抛 `DBError`（界面显示解析失败）。

### 看门狗

* `tests/test_db_embed.py`：内置表结构与**当前游戏数据一致**（等价 `--check`）、
  兜底链、以及**解除打断后必须回到游戏目录**（不留污染）。
* `tests/test_bundle_db_table.py`：把 exe 拷进一个「Data 里只有一张坏掉的
  `Skills.rvdata2`」的沙箱跑自检 → 断言 `名字表: 内置表`、技能名仍对、
  `结果: OK`、没有 error.log。**这条就是「资源忘了打包进 exe」的看门狗。**

### 一个顺手修掉的陈旧 bug

`datatables._plain_path()` 解出来的明文缓存原本只按表名命名
（`tools\_plain\Data_Skills.rvdata2.bin`），**永不失效** —— 游戏更新换了
`Data\X.rvdata2` 之后会一直用旧表（静默读到过期数据）。现在缓存名带上
源文件指纹（大小 + mtime）。

## 10. 发版流程（照这个顺序做）

```powershell
# 1) 改 CHANGELOG.md：在最上面加一段 `## vX.Y.Z · YYMMDD HH:MM`（**写到分钟**，
#    日期用紧凑式 YYMMDD，如 `## v2.201-beta.12 · 261003 17:30`）
#    ⚠ 发版日期只写这一处 —— Release 的标题**与正文首行**都从这儿取（tools/release.py）
# 2) 改 tools/build.py 的 APP_VERSION（版本号唯一来源）；顺手改 使用说明.txt 首行
#    （首行版本号写岔了，打包时会打一行 `!` 提示）
# 3) 打包 + 看门狗 + 全量回归
XJ_PY=D:/Dev/Python/Env/Python312/python.exe python tools/pack_only.py
python tools/check_pack.py            # A 组必须 NG、B 组必须 OK，退出码 0
python tools/run_tests.py             # 19 组全绿（含 dist / bundle_db）
# 4) 提交推送，再发 Release —— ⚠ tag 推不推，两条线不一样
git commit …                          # 版本号相关改动（CHANGELOG / build.py / 使用说明）
git tag v<APP_VERSION>
#   * main（尝鲜版 v0.x）＝ 正式发布：分支和 tag 一起推
git push origin main v<APP_VERSION>
#   * beta（内测版 2.201-beta.N）＝ **平时不公布产物**（川定 2026-10-05）：
#     只推分支、**别推 tag** —— release.py 按 APP_DRAFT=True 存成 Draft，
#     此时 Releases 页不列、非协作者 404、**tag 也不存在**（GitHub 到 publish 才建）
git push origin beta
python tools/release.py               # 标题/正文首行自动带 CHANGELOG 里的发版日期
                                      # --target 取 APP_VERSION_LINE（beta＝beta）、
                                      # --prerelease 取 APP_PRERELEASE、--draft 取 APP_DRAFT
                                      # ⇒ 两条线不会发错，内测版也不会漏存草稿
#   要公开某个内测版：python tools/release.py --publish
```

* 版本号规则：**大功能抬 MINOR、修 bug 只走 PATCH**，不兼容才 MAJOR。
  判据是「用户能不能说出多了什么新能力」；改呈现 / 改习惯 / 补提示一律 PATCH。
* Release 正文 = **段标题（带发版日期）→ 更新日志正文 → `---` → 免责声明 → 一行下载**，
  与画迹1 同一套规则。别往正文里堆下载说明（旧版那段长「## 下载 / 用法」已删）。
  标题 = `<段标题> —— <更新总结首行>`。
* **一个版本只打一个标签**（别用 `--tags`）。两条线共用一个仓库、tag 全仓库唯一，
  所以版本号不会撞（main＝`v0.x`、beta＝`v2.201-beta.N`）。
* ⚠ **beta 线发版只推分支、不推 tag**（2026-10-05 川定）：`gh release create --draft` 期间
  GitHub **不创建 tag**，到 `--publish` 那一刻才建 ⇒ 连版本号都不对外露。tag 一旦
  `git push` 上去就公开了（Tags 页、`git ls-remote` 都看得到），Draft 只挡得住 Release 对象。
  历史遗留：`v2.201-beta.13` 当初先推了 tag 再建 release，那个 tag 还在。
* Release 上**只挂一个 zip**（`RELEASE_ASSETS` 里就一条），别再加附件 ——
  散着挂就一定有人只下主程序。`tools/release.py` 只读 `build.py` 里的这份清单，
  别在命令行手敲附件名。
* 打包链**不会碰** `src/native/XJCodec32.exe`（用 `tools/pack_only.py` 跳过热编译）；
  真跑了 `tools/build.py` 之后记得 `git checkout -- src/native/XJCodec32.exe`。
* 连 GitHub 走本地代理：`git -c http.proxy=http://127.0.0.1:7890 …`，
  推送前 `gh auth setup-git`；核对推送别信 `git log origin/main..HEAD`
  （本机 safe-delete 钩子会吞 tracking ref），用 `git ls-remote`。
